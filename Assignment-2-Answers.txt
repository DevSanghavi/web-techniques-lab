### **1. Concept Explanation**

* **What is the Document Object Model (DOM)?**
  * The **Document Object Model (DOM)** is a standard W3C (World Wide Web Consortium) programming interface for web documents.
  * It represents an HTML document as a hierarchical **tree structure of objects**, where every page element, attribute, and text snippet is converted into a accessible node object.
  * The root of this tree is the `document` object. Through the DOM, JavaScript can dynamically access, modify, add, or delete HTML elements, attributes, and CSS styles in real time without reloading the page.

* **DOM Access Methods (Finding Elements):**
  1. `document.getElementById("id")`: Finds a single unique element by its ID attribute.
  2. `document.getElementsByTagName("tag")`: Finds all elements with a specific HTML tag (returns a live `HTMLCollection`).
  3. `document.getElementsByClassName("class")`: Finds all elements sharing a specific CSS class name (returns an `HTMLCollection`).
  4. `document.querySelector("selector")` / `querySelectorAll("selector")`: Finds element(s) matching any standard CSS selector (e.g., `#id`, `.class`, `tag.class`).

* **DOM Manipulation Methods & Properties (Modifying Content & Tree):**
  1. `element.innerHTML`: Reads or updates HTML content inside an element.
  2. `element.textContent`: Reads or sets plain text content (ignoring HTML tags).
  3. `element.style.property`: Directly changes CSS styling properties (e.g., `style.color`, `style.backgroundColor`).
  4. `element.setAttribute("attr", "value")`: Dynamically alters an element's attribute.
  5. `document.createElement("tag")`: Creates a new element node in memory.
  6. `parent.appendChild(child)`: Appends a node as the last child of a parent element.
  7. `element.remove()` / `parent.removeChild(child)`: Removes an element node from the DOM tree.

### **3. Key Implementation Highlights**

1. **DOM Selection Methods Demonstrated:**
   * `document.getElementById("mainHeading")`: Fetches the heading by unique ID.
   * `document.getElementsByClassName("description")`: Returns an array-like list of elements matching the class name.
   * `document.querySelector("#targetSpan")`: Selects elements using standard CSS syntax (`#id`, `.class`).

2. **DOM Content & Style Manipulation:**
   * Uses `heading.innerHTML` to inject HTML markup dynamically.
   * Uses `span.textContent` to safely assign plain text without HTML evaluation.
   * Modifies inline CSS properties dynamically using `heading.style.color` and `paragraphs.style.backgroundColor`.

3. **Node Creation & Tree Modification:**
   * `document.createElement("li")`: Constructs a new element node in browser memory.
   * `list.appendChild(newItem)`: Injects the newly created element at the end of the `<ul>` container node.
   * `list.lastElementChild.remove()`: Safely detaches and deletes the targeted node from the DOM tree.

### **1. Concept Explanation**

* **Event Listeners (`addEventListener`):**
  * An event listener is a mechanism attached to DOM nodes that executes a handler function when a specified event (such as `click`, `mouseover`, or `submit`) occurs.
  * `element.addEventListener(event, function, useCapture)` is the preferred W3C standard method. Unlike inline HTML handlers or DOM properties (e.g., `onclick`), `addEventListener()` allows multiple event handlers on a single element without overwriting existing ones and can be removed using `removeEventListener()`.

* **Event Propagation & Event Flow:**
  When an event occurs on an element nested inside other elements, the event travels through the DOM tree hierarchy in three distinct phases:
  1. **Capturing Phase (Trickling):** The event travels downward from the outermost ancestor (`window` / `document`) down through intermediate parents to the target element. This phase is activated by setting the third parameter of `addEventListener` to `true`.
  2. **Target Phase:** The event reaches the actual target element where the user interaction originated.
  3. **Bubbling Phase:** The event travels upward from the target element back through its parent elements to the root. This is the default behavior when `useCapture` is set to `false` or omitted.

* **Controlling Propagation:**
  * **`event.stopPropagation()`:** Halts the journey of the event through the DOM tree, preventing parent elements from receiving the event during bubbling or capturing.
  * **`event.preventDefault()`:** Prevents the browser's default action associated with the event (such as preventing a form from submitting or a link from navigating).

### **1. Concept Explanation**

* **Event Propagation:** When an event occurs on a DOM element nested inside other parent elements, the event does not exist in isolation. It travels through the DOM hierarchy in two distinct phases:
  1. **Event Capturing (Trickling Phase):** 
     * The event originates at the outermost ancestor (`window` \\(\rightarrow\\) `document` \\(\rightarrow\\) `<html>` \\(\rightarrow\\) `<body>`) and travels **downwards** through intermediate parent elements until it reaches the target element.
     * To capture events during this downward phase, set the third parameter (`useCapture`) of `addEventListener()` to **`true`** (e.g., `element.addEventListener('click', handler, true)`).
  2. **Event Bubbling (Bubbling Phase):** 
     * Starts at the target element where the user interaction took place and travels **upwards** through parent elements back to the root of the DOM tree.
     * This is the default behavior in JavaScript when the `useCapture` argument is set to **`false`** or omitted (e.g., `element.addEventListener('click', handler, false)`).

* **Controlling Propagation (`event.stopPropagation()`):**
  * The `event.stopPropagation()` method can be called inside any event handler to halt the further flow of the event during either the capturing or bubbling phase.

      cards[name].box.classList.add("flash");
      setTimeout(function () { cards[name].box.classList.remove("flash"); }, 300);

      }

    zone.onmouseover = function (e) {

    zone.onclick = function (e) {

    window.onload = function (e) {
      state.textContent = "window.onload: page loaded, now interact with this box";
      fire("onload", e, "window loaded after " + Math.round(performance.now()) + " ms");
    };
  </script>

### **1. Concept Explanation**

* **Form Processing:** Intercepting the standard HTML form submission using JavaScript to inspect, manipulate, or send user inputs without triggering a full webpage reload.
* **Accessing Form Data via DOM:**

* **Preventing Default Submission (`event.preventDefault()`):** Calling `e.preventDefault()` inside the form's `submit` event handler cancels the browser's default submission behavior, allowing client-side validation and local data processing to take place first.
* **Client-Side Form Validation:** Validating input values (e.g., checking for empty strings, minimum lengths, or format correctness via regex) before processing. If validation fails, error messages are displayed dynamically to guide the user.

#### **Question 6: Demonstrate `alert()`, `confirm()`, and `prompt()` popup boxes.** *(1 Mark)*

---

### **1. Concept Explanation**

JavaScript provides three built-in modal dialog boxes through the browser's `window` object. These dialog boxes are **synchronous/modal**, meaning they pause script execution and freeze interaction with the web page until the user dismisses the dialog box.

1. **`alert(message)`:**
   * **Purpose:** Displays an informational pop-up dialog box containing a message and a single **"OK"** button.
   * **Return Value:** Returns `undefined`. It is strictly used to notify or warn the user.
2. **`confirm(message)`:**
   * **Purpose:** Displays a decision dialog box with a message and two action buttons: **"OK"** and **"Cancel"**.
   * **Return Value:** Returns a boolean value—`true` if the user clicks **"OK"**, or `false` if the user clicks **"Cancel"** or closes the window.
3. **`prompt(message, defaultValue)`:**
   * **Purpose:** Displays an input dialog box prompting the user to enter text, along with an optional default input value, **"OK"**, and **"Cancel"** buttons.
   * **Return Value:** Returns the string entered by the user if **"OK"** is clicked, or `null` if the user clicks **"Cancel"** or closes the box.

### **1. Concept Explanation**

* **What is jQuery?**
  * **jQuery** is a fast, lightweight, and free open-source JavaScript library created by **John Resig in 2006**.
  * Its core motto is **"Write less, do more"**.
  * It simplifies HTML DOM document traversal and manipulation, event handling, CSS animations, and AJAX requests while resolving cross-browser inconsistencies so your code executes identically across all browsers.

* **Installation Methods:**
  1. **Option 1: Content Delivery Network (CDN) (Recommended / Easiest):**
     Includes jQuery directly from a remote Content Delivery Network (e.g., `code.jquery.com`) using a `<script>` link. No local file download is required.
     ```html
     <script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
     ```
  2. **Option 2: Local File Download:**
     Download `jquery-3.7.1.min.js` from `jquery.com`, save it inside your local project folder (e.g., `js/`), and reference it with a local script tag.
     ```html
     <script src="js/jquery-3.7.1.min.js"></script>
     ```

* **Basic jQuery Syntax:**
  * The fundamental jQuery formula is:
    ```javascript
    $(selector).action();
    ```
    * **`$`**: Defines or accesses jQuery.
    * **`(selector)`**: Finds or queries HTML element(s) using standard CSS selector syntax (e.g., `"p"`, `"#id"`, `".class"`, `"*"`).
    * **`.action()`**: The jQuery method to be performed on the selected element(s) (e.g., `.hide()`, `.show()`, `.css()`, `.text()`, `.fadeIn()`).

* **The Document Ready Event (`$(document).ready()`):**
  * Prevents jQuery code from executing before the browser finishes parsing the document object model (DOM).
  * **Full Form:**
    ```javascript
    $(document).ready(function(){
      // jQuery code goes here
    });
    ```
  * **Shorthand Form:**
    ```javascript
    $(function(){
      // jQuery code goes here
    });
    ```

### **1. Concept Explanation**

jQuery selectors allow developers to find and manipulate HTML elements in the DOM using standard CSS selector syntax. The basic syntax is **`$(selector).action()`**.

* **Universal Selector (`$("*")`):** 
  * Selects **every single element** on the HTML page (e.g., `<html>`, `<head>`, `<body>`, `<div>`, `<p>`, buttons, etc.).
  * Used when applying global styling or clearing attributes across all elements.
* **Element / Tag Selector (`$("tag")`):** 
  * Selects **all elements** sharing the specified HTML tag name (e.g., `$("p")` selects all `<p>` elements, `$("h3")` selects all `<h3>` elements).
* **ID Selector (`$("#id")`):** 
  * Selects a **single unique element** that possesses the matching `id` attribute (prefixed with `#`). In standard HTML, an `id` must be unique per document.
* **Class Selector (`$(".class")`):** 
  * Selects **all elements** that share the matching CSS class name (prefixed with `.`). A class can be reused across multiple elements of different tag types.

### **1. Concept Explanation**

In jQuery, **event methods** attach handler functions to HTML elements to respond dynamically when browser events or user actions occur.

* **Syllabus Event Methods Overview:**
  1. **`click()`:** Triggers when an HTML element is clicked once.
  2. **`dblclick()`:** Triggers when an element is double-clicked (two rapid clicks).
  3. **`blur()`:** Fires when a form control loses focus (e.g., when the user clicks or tabs away from an input box).
  4. **`change()`:** Fires when the value of a form element (`<input>`, `<select>`, or `<textarea>`) is changed.
  5. **`bind()` (Legacy):** Attaches event handlers to selected elements (modern projects use `.on()`).
  6. **`die()` (Removed in jQuery 1.9):** Used to remove event handlers attached via `.live()` (replaced by `.off()` in modern jQuery).
  7. **`error()` (Removed in jQuery 3.0):** Triggered when an element (such as an `<img>`) failed to load (replaced by `.on("error", fn)`).

### **1. Concept Explanation**

jQuery simplifies Document Object Model (DOM) manipulation by providing intuitive methods to retrieve and modify HTML content, attributes, element nodes, and CSS styles without writing verbose vanilla JavaScript.

#### **Core Categories of jQuery DOM Manipulation Methods:**

1. **Content & Value Methods (`text()`, `html()`, `val()`):**
   * **`text()`**: Gets or sets the combined plain text content of selected elements (strips HTML tags).
   * **`html()`**: Gets or sets the inner content of selected elements, including HTML markup.
   * **`val()`**: Gets or sets the input value of form controls (e.g., `<input>`, `<select>`, `<textarea>`).
   * *Rule:* Passing no argument retrieves (gets) the value; passing an argument updates (sets) it.

2. **Element Insertion & Deletion Methods (`append()`, `prepend()`, `after()`, `before()`, `remove()`, `empty()`):**
   * **`append()`**: Inserts content **inside** the selected element at the end.
   * **`prepend()`**: Inserts content **inside** the selected element at the beginning.
   * **`after()`**: Inserts content **outside** and after the selected element.
   * **`before()`**: Inserts content **outside** and before the selected element.
   * **`remove()`**: Deletes the selected element along with all its child nodes.
   * **`empty()`**: Clears all child nodes and text content from inside the selected element while keeping the element itself.

3. **Attribute & CSS Methods (`attr()`, `addClass()`, `removeClass()`, `css()`):**
   * **`attr("name", "value")`**: Reads or modifies element attribute values (e.g., `src`, `href`, `title`).
   * **`addClass("class")` / `removeClass("class")` / `toggleClass("class")`**: Dynamically adds, removes, or toggles CSS classes.
   * **`css("property", "value")`**: Directly gets or sets inline CSS style properties.

---

### **1. Advantages of jQuery**

1. **Simplified & Concise Syntax:** Adheres to the motto *"Write less, do more"*, allowing complex DOM operations to be executed in significantly fewer lines of code compared to plain JavaScript.
2. **Cross-Browser Compatibility:** Handles cross-browser inconsistencies internally, ensuring identical behavior across Chrome, Firefox, Edge, and Safari.
3. **Built-in Effects & Animation:** Features built-in methods for hiding/showing elements, sliding, fading (`fadeIn()`, `fadeOut()`), and custom animations (`animate()`) without needing complex CSS/JS scripts.
4. **Simplified AJAX Support:** Offers easy-to-use asynchronous methods (such as `.load()` and `$.get()`) to update portions of a page dynamically without a full page reload.
5. **Vast Ecosystem & Plugin Support:** Provides access to an extensive ecosystem of community plugins (e.g., jQuery UI widgets like datepickers and tabs).
6. **Free & Open Source:** Free to use and easily integrated via local files or remote CDNs.

---

### **2. Disadvantages of jQuery**

1. **Extra Overhead & File Size:** Requires downloading an external library file (around 30 KB minified), which adds HTTP request overhead during initial page load.
2. **Slower Execution than Plain JS:** Abstracting native DOM methods creates performance overhead, making it slower than pure vanilla JavaScript for heavy computations or large DOM trees.
3. **Redundancy with Modern Web APIs:** Modern JavaScript (ES6+) now includes powerful native capabilities (`querySelectorAll()`, `fetch()`, `classList`) that perform the same tasks without needing an external library.
4. **Plugin Conflicts & Slowdown:** Including too many third-party jQuery plugins can cause script conflicts and degrade overall website performance.
5. **Breaking Changes & Deprecations:** Newer versions of jQuery have removed older methods (e.g., `live()`, `die()`, and `error()`), which can break legacy codebases during library updates.

#### **Q3. JSON (7 Marks)**
#### **Question 1: Explain JSON and its characteristics.** *(1 Mark)*

---

### **1. Concept Explanation**

* **What is JSON?**
  * **JSON** stands for **JavaScript Object Notation**. It is a lightweight, text-based data-interchange format popularized by **Douglas Crockford** in the early 2000s.
  * It is designed to be **easy for humans to read and write** and **easy for machines to parse and generate**.
  * It is the standard data format for modern Web APIs, mobile applications, microservices, and server-client data communication.
  * **File Extension:** `.json`
  * **MIME Type:** `application/json`

* **Core Characteristics of JSON (from Unit 5 notes):**
  1. **Lightweight & Fast:** Uses a simple syntax without heavy markup or redundant end tags (unlike XML), reducing data size and bandwidth usage over network requests.
  2. **Language-Independent:** Although based on a subset of JavaScript object syntax, JSON is plain text. Virtually all modern programming languages (Python, Java, PHP, C#, C++, etc.) have built-in parsers for JSON.
  3. **Self-Describing & Readable:** Data is structured as intuitive `name: value` pairs, making the schema easy to understand without external documentation.
  4. **Hierarchical (Nested):** Supports tree-like data structures where objects can contain nested objects and arrays of items.
  5. **Text-Based:** Consists entirely of UTF-8 plain text, enabling safe transmission across web servers and firewalls.

### **1. Concept Explanation**

* **JSON Data Structures:**
  1. **JSON Object (`{}`):** An unordered collection of key-value pairs enclosed in curly braces.
  2. **JSON Array (`[]`):** An ordered list of values enclosed in square brackets. Array elements can be strings, numbers, booleans, objects, or other arrays.

* **Supported JSON Data Types (6 Valid Values):**
  * **String:** Text enclosed strictly in double quotes (e.g., `"M.Sc. IT"`).
  * **Number:** Floating-point or integer values written without quotes (e.g., `101`, `92.5`).
  * **Boolean:** Lowercase `true` or `false` without quotes.
  * **Null:** Represents an intentional empty value using the lowercase keyword `null`.
  * **Object:** Nested name/value pairs enclosed in `{}`.
  * **Array:** Ordered collection of items enclosed in `[]`.
  * *(Note: Functions, `undefined`, `Date` objects, and `NaN` are **not** permitted in JSON).*

* **Strict JSON Syntax Rules:**
  1. **Keys in Double Quotes:** Every key/property name **must** be wrapped in double quotes.
  2. **Double Quotes for Strings:** String values **must** use double quotes (single quotes cause a syntax error).
  3. **Comma Separators:** Multiple key-value pairs or array elements must be separated by commas.
  4. **No Trailing Commas:** A comma **cannot** follow the last item or property in an object/array.
  5. **No Comments Allowed:** JSON does not support `//` or `/* */` comments.

### **Unit 5 – JavaScript Object Notation (JSON)**

#### **Q3. JSON (7 Marks)**
#### **Question 5: Explain the advantages and disadvantages of JSON.** *(1 Mark)*

---

### **1. Advantages of JSON**

1. **Lightweight & Fast Transfer:** JSON uses minimal text markup without redundant closing tags (unlike XML), reducing data payload size and speeding up network transmission over APIs.
2. **Easy to Read & Write:** Features a clean, self-describing key-value structure that makes data simple for developers to inspect and understand.
3. **Language-Independent:** Although derived from JavaScript object syntax, JSON is plain text supported by virtually all modern programming languages (Python, Java, PHP, C#), making cross-platform data exchange seamless.
4. **Native JavaScript Integration:** Converts effortlessly between JSON strings and JavaScript objects using built-in methods (`JSON.parse()` and `JSON.stringify()`).
5. **Fast Parsing & High Performance:** Translates directly into native runtime memory structures far more quickly than complex XML DOM tree parsing.
6. **Widespread Industry Adoption:** Standard data format across modern RESTful web APIs, mobile applications, microservices, and NoSQL databases like MongoDB.

---

### **2. Disadvantages of JSON**

1. **No Comment Support:** Standard JSON strictly forbids comments (`//` or `/* */`), making it challenging to document configuration files or add notes directly within the dataset.
2. **Strict & Unforgiving Syntax:** Minor formatting mistakes—such as using single quotes instead of double quotes, missing quotes around keys, or leaving a trailing comma—will cause parsing to fail completely.
3. **Limited Supported Data Types:** Lacks built-in support for complex data types like `Date` objects, `Function`, `undefined`, or binary data, forcing them to be converted into strings.
4. **No Built-in Schema or Validation:** Standard JSON does not natively enforce structural data types or schema constraints without using external schema tools.
5. **Requires Transport Security:** Plain JSON text transmitted over network connections does not provide native encryption, requiring HTTPS and input sanitization to ensure data integrity.

---

### **3. Quick Comparison: JSON vs. XML**

| Feature | JSON | XML |
| :--- | :--- | :--- |
| **Data Size** | **Smaller & lightweight** (No closing tags) | **Larger** (Requires opening/closing tags) |
| **Parsing Speed** | **Fast** (Parses natively into objects) | **Slower** (Requires DOM parser tree) |
| **Data Types** | Supports String, Number, Boolean, Null, Object, Array | All data is treated strictly as plain text |
| **Comments** | **Not allowed** | Supported (`<!-- comment -->`) |
| **Primary Use Case** | **Web APIs, mobile apps, and microservices** | Document markup and legacy enterprise systems |
